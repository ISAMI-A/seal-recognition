## 1. 项目概述与整体流程

### 1.1 背景与目标

公章（单位印章）是各类公文、合同、证件上的关键凭证，其上排布的环形单位名称是印章归属判定的核心依据。传统人工核对效率低、易出错，本系统目标是**自动从扫描件/图片中定位印章，并识别出印章所刻的单位全称**，输出结构化结果（单位名 + 置信度 + 识别方法）。

### 1.2 端到端流程

系统采用「**检测—识别**」两阶段流水线：

```
PDF / 图片
   │
   ├─ ① PDF 渲染（PyMuPDF, 300 DPI）  ────  仅 PDF 输入时
   │
   ├─ ② 印章检测（YOLOv8n）────────── 定位并裁剪出印章区域
   │
   ├─ ③ 预处理（形状/颜色自适应、极坐标展开等）
   │
   ├─ ④ 文字识别（PaddleX seal_recognition / PaddleOCR）
   │
   ├─ ⑤ 后处理（碎片合并、文本清理、领域知识纠错、投票决策）
   │
   └─ ⑥ 结构化输出（单位名称 / 置信度 / 方法）→ CSV / JSON / Web 展示
```

### 1.3 两种识别模式

| 模式 | 定位 | 关键特点 |
|------|------|---------|
| **福州专区（fuzhou）** | 红色圆形印章 | 极坐标展开 + 多策略投票 + 福州单位知识库（形近字纠错/前缀补全/编辑距离纠错） |
| **通用专区（general）** | 多颜色多形状印章 | 形状检测（圆/椭圆/矩形）+ 仿射拉正 + 自适应颜色增强，无地区限定 |

## 2. 系统架构与模块划分

```
testAI/
├── yolo/                 # 检测阶段（PyTorch 生态）
│   ├── models/印章识别模型.pt    # YOLOv8n 单类印章检测模型（约 6.25 MB）
│   ├── launcher.py / detect.py   # 检测 + 裁剪
│   ├── predict.py / export_labelu.py  # 模型预标注 → labelU 半自动标注闭环
│   └── tools/render_pdf.py       # PDF → PNG 渲染
├── ocr/                  # 识别阶段（飞桨生态）
│   ├── fuzhou/           # 福州专区：engine / extract / pipeline
│   └── tongyong/         # 通用专区：engine / extract / pipeline
├── web/                  # Web 系统
│   ├── backend/          # FastAPI（routers/services）
│   └── frontend/         # React 19 + Vite + TypeScript
├── data/                 # 数据集与中间产物
├── ocr_venv/             # OCR + Web 后端虚拟环境（飞桨）
└── venv/                 # YOLO 检测虚拟环境（PyTorch）
```

**架构要点**：

- **双框架双虚拟环境隔离**：检测用 PyTorch 生态（ultralytics），识别用飞桨生态（PaddleOCR/PaddleX），两套环境彼此独立，避免依赖冲突。Web 后端运行在 `ocr_venv`，调用 YOLO 时通过**子进程**切换到 `venv` 的 Python 解释器执行。
- **分层职责清晰**：每个专区都是 `engine.py`（图像预处理 + OCR 引擎封装）→ `extract.py`（文本后处理 + 领域知识）→ `pipeline.py`（多策略编排 + 投票）三件套，符合「预处理 / 识别 / 后处理」分层思想。

## 4. 印章检测模块（YOLO）

### 4.1 模型

- 模型文件：`印章识别模型.pt`，大小 **6,251,492 字节（约 6.25 MB）**。
- 通过读取 checkpoint 内 `model.yaml` 确认网络缩放参数为 `depth_multiple=0.33`、`width_multiple=0.25`，对应 **YOLOv8n（nano）** 结构；`nc=1` 单类别（`seal`），属轻量级检测模型。

### 4.2 检测流程

```python
results = model.predict(img, conf=0.25, iou=0.5, imgsz=640, device="cuda:0")[0]
# 遍历 results.boxes，取 xyxy 绝对像素坐标，numpy 切片裁剪
crop = img[y1:y2, x1:x2]
```

| 参数 | 值 | 作用 |
|------|-----|------|
| `conf` | 0.25 | 置信度阈值，低于此分的框被丢弃 |
| `iou` | 0.5 | NMS 的非极大值抑制 IoU 阈值（重叠框去重，由 ultralytics 内部完成） |
| `imgsz` | 640 | 输入统一等比缩放（letterbox）到 640×640 |
| `device` | cuda:0 | GPU 推理 |

裁剪结果按 `{原文件名}_seal{序号}.jpg` 命名，同一文件多枚印章按序号递增保存。

### 4.3 PDF 前端渲染（render_pdf.py）

PDF 坐标单位为 point（1/72 英寸），要得到目标 DPI 位图需按比例放大：

```python
zoom = dpi / 72             # 300 DPI → zoom ≈ 4.167
matrix = fitz.Matrix(zoom, zoom)
pix = page.get_pixmap(matrix=matrix)
```

- 默认 **300 DPI**，兼顾印章细节清晰度与显存占用。
- 输出命名为 `{PDF名}_page{001}.png`（三位补零），保证检测阶段 `sorted()` 遍历时页序稳定。
- `batch_render_pdf()` 对每个 PDF 单独 try/except，单个失败不中断整体。

### 4.4 数据标注闭环（半自动标注 / 主动学习）

这是本项目在**数据工程**上的核心实践：

```
成品模型 ──预测──> YOLO txt 标签 + labelU 预标注 JSON
                          │
         人工在 labelU 中校验：✓保留  ✗删错  ＋补漏
                          │
         导出 YOLO 训练格式 ──> 合并回训练集 ──> 迭代训练
```

- `predict.py`：用已训练模型对新图批量预标注，一份输入同时产出 YOLO 标签与 labelU JSON 供人工精修。
- `export_labelu.py`：整合多来源图片（目录/单文件混排），含同名文件自动加父目录前缀去重。
- 坐标归一化做了**防御性裁剪**（clamp 到 [0,1]），避免越界框污染训练标签。

### 4.5 数据集规模（实测统计）

| 数据集 | 数量 | 说明 |
|--------|------|------|
| 训练集 `v6/images/train` | 450 | 含平行 labels |
| 验证集 `v6/images/val` | 113 | 含平行 labels |

## 5. OCR 识别引擎基础

### 5.1 双后端设计

`OCREngine(backend=...)` 封装两种可切换后端：

| 后端 | 引擎 | 特点 |
|------|------|------|
| `paddleocr_seal`（默认） | PaddleX `seal_recognition` 流水线 | 印章专用，速度快，输出自带圆形阅读顺序 |
| `paddleocr` | PaddleOCR 3.x 通用引擎 | 通用兜底，兼容多种返回格式 |

**seal_recognition 关键调用**：

```python
from paddlex import create_pipeline
pipe = create_pipeline(pipeline="seal_recognition")
res = pipe.predict(img, use_layout_detection=False)  # 输入已是裁剪印章图，关闭版面检测
```

结果解析 `_recognize_paddle_seal` 读取 `seal_res_list` 中的 `rec_texts/rec_scores/rec_boxes`，并为每条写入 `_seal_order` 顺序标记——**刻意保留外环→内环、顺时针的天然阅读顺序，不做置信度重排**，为后续碎片合并提供正确顺序依据。

**paddleocr 通用引擎**关闭了文档方向分类、文档展平、文本行方向等不必要模块（`use_doc_orientation_classify=False` 等），并通过 `_parse_paddle_result` 用一个解析器**兼容 PaddleOCR 2.x/3.x 的 4 种返回格式**，降低框架升级的适配成本。

### 5.2 图像预处理基础算子（能力库）

#### 颜色通道增强

**红色通道提取（经典红章处理）** `extract_red_channel`：利用朱红印文 R 通道远大于 G/B 的特点：

```python
r_enhanced  = convertScaleAbs(r, alpha=2.0, beta=0)     # 红 ×2 增强
g_suppressed= convertScaleAbs(g, alpha=0.5, beta=-50)   # 绿减半再减 50
b_suppressed= convertScaleAbs(b, alpha=0.5, beta=-50)   # 蓝减半再减 50
red_response= subtract(r_enhanced, addWeighted(g_suppressed, 0.5, b_suppressed, 0.5, 0))
red_response= normalize(red_response, 0, 255, NORM_MINMAX)
```

**改进版 v2** `extract_red_channel_v2`：用「Lab 空间 a 通道（红绿对立轴）归一化 ×0.65 + HSV 红色掩膜 ×0.35」加权融合，再 CLAHE 增强，目的是**减少笔画粘连、保护边缘细笔画**。

**自适应多颜色增强** `adaptive_color_enhance`：同时计算红/蓝掩膜占比，红章走红通道、蓝章走 `b - 0.3g - 0.3r` 提蓝；否则以「R/G/B/灰度四个通道的**标准差**」作为对比度客观指标，自动选择对比度最高的通道再做 CLAHE——实现「无颜色假设」的通用增强。

#### 二值化（三种方法）

- `adaptive`（默认）：`adaptiveThreshold(gray, 255, GAUSSIAN_C, BINARY, blockSize=31, C=5)`
- `otsu`：全局大津阈值
- `triangle`：三角阈值

颜色判定 `detect_seal_color`：HSV 色环两端（H∈[0,15]∪[160,180]）红色占比 **> 1.5%** 判为红章。

#### 形态学去噪 `denoise_seal`

椭圆核（默认 3×3）先**开运算**（去孤立噪点）再**闭运算**（连接断裂笔画）。

#### 多版本预处理 `preprocess_multi_version`

一次生成 5 个版本供后续「多策略 OCR」挑选，避免单一路径二值化失败导致整体失败：

```python
{
  "color":  原图加白边,
  "gray":   灰度图,
  "clahe":  两级 CLAHE（先 3.0/(8,8) 再 2.0/(4,4)），不二值化保留细节,
  "red":    红通道增强（红章用 v2，非红章回退 clahe）,
  "binary": 高斯模糊 + 自适应二值化(31,C=7) + 去噪 + 反转为白底黑字,
}
```

### 5.3 圆形检测与极坐标展开

公章单位名称沿圆周排布，直接 OCR 弧形文字效果差。系统用**极坐标展开**把弧线拉直成水平文字：

```python
polar = cv2.warpPolar(img, (800, 200), (cx, cy), radius,
                      cv2.INTER_LINEAR + cv2.WARP_POLAR_LINEAR + cv2.WARP_FILL_OUTLIERS)
```

**圆心检测 `detect_seal_circle`（双策略）**：

1. 霍夫圆 `HoughCircles(blurred, HOUGH_GRADIENT, dp=1.2, minDist=40, param1=80, param2=30, minRadius=20)`，取半径最大者；
2. 失败则回退 Canny 边缘 + 最小外接圆拟合，并用**圆度校验** `0.25 < 轮廓面积/圆面积 < 1.35` 剔除月牙形等非圆闭合轮廓。

**多半径择优 `auto_polar_unwrap`**：不赌单一半径，尝试 `[0.92, 0.88, 0.82, 0.75]` 四个展开半径比，以「非零像素占比」作为清晰度指标自动选最优展开图。

**内外环分层 `polar_unwrap_ring`**：按公章结构分层——外环（0.65R~1.0R，单位名称区）与内环（0.30R~0.65R），通过环形掩膜分别展开，精准命中目标文字区域。

### 5.4 圆形阅读顺序恢复 `sort_circular_text`

对每条 OCR 结果取 bbox 中心，用 `atan2` 求角度，经 `(-angle_deg + 90) % 360` 换算为「从正上方起、顺时针」的 0~360°，据此恢复圆形章文字的阅读顺序。

### 5.5 形状检测与仿射拉正（通用专区核心能力）

**形状检测 `detect_seal_shape`** 按优先级判定：

1. 霍夫圆 + 圆度/重叠率校验（`overlap > 0.05`）；
2. 椭圆拟合 `fitEllipse`，以长轴/短轴 `aspect ≥ 1.8` 区分圆与椭圆；
3. 矩形逼近 `approxPolyDP`（四顶点 → `minAreaRect`）；
4. 兜底统一按矩形处理。

**仿射拉正 `warp_ellipse_to_circle`**：

- 圆 → 原样返回；
- 椭圆 → 计算长短轴比 `scale`，直接修改仿射矩阵对角线做**单轴拉伸**，把椭圆拉成圆；
- 矩形 → `boxPoints` 取四顶点 + `getPerspectiveTransform` 透视变换摆正。

## 6. 福州专区：预处理与多策略识别

### 6.1 处理流程

```
输入印章图
  → 霍夫圆检测 + 极坐标展开（多半径择优）
  → 多版本预处理（gray/clahe/red/binary/color）
  → 多策略 OCR 识别
  → 投票决策
  → 福州专属后处理（结构评分 / 知识库纠错 / 编辑距离）
  → 输出单位名称
```

### 6.2 快速路径 + 回退架构

- 默认先走 `paddleocr_seal` 专用流水线（快速路径），结果**带数字前缀或置信度 < 0.70** 时，回退到通用多策略路径。
- 通用多策略路径保留多版本预处理与极坐标展开等全部「重型」预处理，作为兜底。
- 「专业模型加速 + 通用模型纠错兜底」的混合设计。

### 6.3 多策略投票 `_vote_for_best`

8 类策略并行产出候选，按实测正确率差异化加权后投票：

| 策略 | 权重 | 输入 | 作用 |
|------|------|------|------|
| `polar_outer` | 1.8 | 外环极坐标展开 | 最高权重（单位名所在区域） |
| `upscaled` | 1.3 | 2 倍放大图 | 提升小印章识别率 |
| `polar` | 1.3 | 全环极坐标展开 | 弧形文字拉直 |
| `text_ring` | 1.2 | 环形文字区域 | 剔除中心五角星干扰 |
| `polar_inner` | 1.5 | 内环极坐标展开 | - |
| `direct` | 0.8 | 原图 | 基线 |
| `color_red`/`color_blue` | 0.7 | 颜色增强图 | 正确率较低，降权 |
| `fallback_*` | 1.0 | CLAHE LAB 增强 / 降采样 | 兜底 |

投票优先选择「多策略一致」的结果，全部失败则回退 CLAHE 增强 + 降采样重试。

## 7. 福州专区：领域知识后处理

这是最具**领域特色**的部分，核心思想：**通用结构模型粗筛 → 福州本地知识库精准纠错补全**。

### 7.1 机构结构评分 `org_structure_score`

用四套打分字典替代硬编码名单，作为第一道防线：

| 评分字典 | 规模 | 规则 |
|----------|------|------|
| `REGION_SCORES` | ~38 条 | 行政区划前缀命中 +8/+10 |
| `SUFFIX_SCORES` | ~40 条 | 单位后缀（局/厅/委/办/公司/委员会等）取最长命中 +6~+10 |
| `ORG_KEYWORD_SCORES` | ~22 条 | 机构特征词（人民/大学/委员会/共青团等）+4~+8 |
| `BODY_PENALTY` | ~40 条 | 正文词（通知/报告/姓名/电话等）扣 -4~-10 |

综合长度、纯数字/符号惩罚等规则，**总分 ≥ 8 判定为有效单位名**。

### 7.2 福州专属知识库四大件

| 数据结构 | 规模 | 用途 |
|----------|------|------|
| `KNOWN_ORGANIZATIONS` | ~50 条 | 福州真实单位全称列表 |
| `KNOWN_ORG_ALIASES` | ~40 条 | 别名/残缺 → 全称映射 |
| `SEAL_CORRECTION_MAP` | ~100 条 | 形近字纠错表（含 22 个「×州市」→福州市） |
| `PREFIX_MAP` + `GENERIC_PREFIX_RULES` | ~24 + ~12 条 | 行政区划/党团前缀补全 |

**典型纠错示例**：

- 形近字：`农休 / 农市 / 农朴` → `农林`；`宾府` → `政府`；`孟山` → `盖山`。
- 地名混淆（福州印章字形易误识）：`广州市 / 漳州市 / 泰州市` 等 → `福州市`；`苍山 / 桃山 / 楚山` → `仓山`。
- 别名补全：`建总集团` → `福州市城乡建总集团有限公司`；`山区河长制` → `福州市仓山区河长制办公室`。

### 7.3 形近字纠错 `correct_similar_chars`（两阶段）

1. **词级**：`SEAL_CORRECTION_MAP` 按错误串长度降序（长匹配优先）替换；对「错误串是正确串子串」的情况只在文本首/尾做边界替换，防止中间级联误替换。
2. **单字级**：对高频单字错误（衣→林、宾→政、孟→盖、车→年）按 `农{X}`、`{X}大`、`人民{X}` 等 8 类上下文模式替换，避免孤立替换误伤。

### 7.4 编辑距离纠错 `levenshtein_auto_correct`

- 经典动态规划实现，用**一维滚动数组**优化空间。
- 候选过滤：长度差 > `max(5, len(text)//2)` 跳过。
- 命中阈值：编辑距离 ≤ `max(1, len(text)//3)` 才返回纠错结果。

### 7.5 已知单位模糊匹配 `match_known_organization`（6 级）

按优先级：别名精确匹配 → 全称精确匹配 → 子串补全 → 反向子串 → 头尾对齐（含 `lstrip("中国共产/中共")` 特例）→ **最长公共子串 + 字符重叠率组合评分**：

```
score = lcs_ratio × 0.7 + overlap × 0.3
# lcs_ratio = LCS长度 / min(len(text), len(known))
# overlap   = |字符集合A ∩ B| / |A ∪ B|（Jaccard）
# 过滤 overlap < 0.4，最终 score ≥ 0.45 命中
```

### 7.6 后验置信度融合

`extract_org_name` 最终综合打分：

```
后验置信度 = 识别置信度×0.35 + 位置得分×0.25 + 语义结构分×0.25 + 长度分×0.15
```

其中位置得分按 bbox 中心离图中心的归一化距离分档（<0.3→1.0，<0.6→0.8，<1→0.5，否则 0.3）。

## 8. 通用专区：形状自适应识别

### 8.1 处理流程

```
输入图 → ① 形状检测（圆/椭圆/矩形）
       → ② 仿射拉正（椭圆→圆，矩形→摆正）
       → ③ seal_recognition 识别（异常/失败则放大 2 倍重试）
       → ④ 碎片合并（按圆形阅读顺序）
       → ⑤ 文本清理 + 有效性判断
       → ⑥ 兜底（放大识别，置信度 ×0.9）
       → 输出
```

### 8.2 文本清理 `clean_text`

| 规则 | 正则 | 示例 |
|------|------|------|
| 前导噪声 | `^[\dA-Za-z\-\(\)]+(?=[\u4e00-\u9fff])` | `21887V深圳市` → `深圳市` |
| 尾部噪声 | `[\dA-Za-z\-\(\)]+$` | `委员会510` → `委员会` |
| 中间单字符噪声 | `(?<=[\u4e00-\u9fff])[\dA-Za-z](?=[\u4e00-\u9fff])` | `有限4公司` → `有限公司` |
| 重复去重 | `(.)\1{2,}` → `\1\1` | `有限限限` → `有限限` |
| 符号过滤 | `PUNCTUATION_FILTER`（含块元素 █▒▓ 等） | 删除印章边框误识符号 |

### 8.3 碎片合并 `merge_seal_texts`

先按 `_seal_order`（外环→内环、顺时针）排序，再贪心合并：

- 以「**合并后是否出现单位名关键词（`ORG_KEYWORDS`）**」作为继续拼接的判据——既能粘回被打散的「××村 + 民委员会」，又能在遇到 `STOP_WORDS`（发票专用章、财务专用章等）或超长数字串时及时切断。

### 8.4 有效性判断 `is_valid_org_name_general`

- 长度 ≥ 6 且含中文 → 直接判为有效单位名（容错）；
- 长度 3~5 字 → 必须命中单位关键词（公司/局/院/所/校 等）才有效；
- 含 `STOP_WORDS` 或纯数字/符号 → 判无效。

## 9. Web 系统

### 9.1 架构

- **后端** FastAPI（运行于 `ocr_venv`），路由分 `ocr / yolo / tune` 三组，业务封装在 `services`。
- **前端** React 19 + Vite 8 + TypeScript 6，经 Vite 代理转发 `/api`、`/static` 到后端。
- CORS 允许前端 dev server（localhost:5173）跨域访问。
- 静态目录挂载上传/裁剪/调优图片，供前端直接展示。

### 9.2 三大功能页面

| 路由 | 页面 | 功能 |
|------|------|------|
| `/yolo` | YOLO 检测 | 上传 PDF/图片 → 检测裁剪 → 缩略图网格 → 发送到 OCR |
| `/ocr` | OCR 识别 | 上传印章图 → 福州/通用模式切换 → 识别 → **过程可视化（预处理图/文字框/置信度）** → 导出 |
| `/tune` | 模型调优 | 交互式框选标注（拖拽/移动/删除/清空）→ 导出 YOLO 训练格式 / JSON 预标注 |

识别结果支持**点击编辑人工修正**，导出前可改错；导出支持 CSV / Excel，可勾选部分结果。

### 9.3 异构环境子进程调用

Web 后端（`ocr_venv`，飞桨）需要调用 YOLO（`venv`，PyTorch）时，通过 `subprocess.run` 直接调用 `venv/Scripts/python.exe` 执行 `yolo/launcher.py`，返回裁剪结果——在单进程内优雅地解决了「两套深度学习框架不可共处同一环境」的难题，并带 300/600 秒超时与错误捕获。

### 9.4 模型调优与标注导出（数据闭环的 Web 化）

- 支持导出 **X-AnyLabeling/labelU 预标注 JSON**：矩形框自动转顺时针四点多边形，`result` 字段按官方约定序列化为 JSON 字符串。
- 支持导出 **YOLO 官方训练包（zip）**：`images/train+val`、`labels/train+val`（归一化 `class cx cy w h`）、`data.yaml`，数据按文件 md5 哈希**固定划分 train 80% / val 20%**（可复现）。

## 10. 关键工程细节与踩坑经验

1. **中文路径全链路兼容**：Windows 下 OpenCV 的 `imread/imwrite` 无法处理中文路径，全项目统一改用 `np.fromfile + cv2.imdecode`（读）、`cv2.imencode(...).tofile(...)`（写）。曾因历史版本用 `imread` 读图尺寸，中文路径退回默认 640×640 导致 YOLO 归一化坐标错误，已修复。

2. **CUDA DLL 路径注入**：`engine.py` 启动时把 `nvidia/cu13/bin/x86_64` 注入 `PATH`，解决 Windows GPU 下 `cublasLt64_13.dll` 找不到的问题，并设 `KMP_DUPLICATE_LIB_OK=TRUE` 规避 OpenMP 多库冲突。

3. **模型缓存重定向**：`PADDLE_PDX_CACHE_HOME` 指向 `D:\paddlex_cache`，把 PaddleX 模型缓存移出 C 盘，且规避中文路径无法作为缓存的坑。

4. **双虚拟环境隔离**：飞桨与 PyTorch 生态分属两个 venv，通过子进程调用打通，避免依赖冲突。

5. **PowerShell 编码**：`start.ps1` 含中文，需保持 UTF-8 with BOM 编码，否则 Windows PowerShell 5.1 解析报错。

6. **临时产物隔离与清理**：PDF 渲染产物放入 `_pdf_rendered` 等带下划线前缀的临时子目录，与最终产物隔离；Web 数据目录 `_web_uploads/_web_crops/_web_tune` 支持 `POST /api/data/clear` 一键清空。

## 11. 创新点与工程亮点

1. **「专业模型加速 + 通用模型兜底」混合识别架构**：默认 seal_recognition 快速识别，结果不可靠时自动回退多策略路径，兼顾效率与准确率。

2. **极坐标展开 + 多半径择优**：将圆形印章的弧形文字通过 `warpPolar` 拉直成水平文字，并以非零像素占比在多半径候选中自动选最优展开；进一步做内外环分层展开精准命中单位名区域。

3. **8 策略多版本识别 + 证据加权投票**：并行生成灰/CLAHE/红/二值/彩色多版预处理图与多种展开方式，按实测正确率差异化加权投票，避免单一预处理路径失败导致整体失败。

4. **领域知识库四件套 + 多级纠错**：已知单位全称 / 别名映射 / 形近字纠错表 / 前缀补全规则层层兜底，针对性解决印章 OCR 的「形近字误识、前缀缺失、后缀遗漏」三大痛点。

5. **鲁棒的双策略圆形/形状检测**：霍夫圆为主、Canny+最小外接圆为兜底，加圆度/重叠率校验；通用专区进一步支持圆/椭圆/矩形自适应与仿射拉正。

6. **半自动标注闭环（主动学习）**：模型预标注 → labelU 人工精修 → 导出训练格式 → 迭代训练，把标注成本大幅摊薄，5000 张原始池精选出 563 张高质量训练集。

7. **异构深度学习环境工程化打通**：飞桨与 PyTorch 分环境隔离，通过子进程调用实现单系统内的统一编排。

8. **中文路径、CUDA DLL、模型缓存、双端环境等十余处工程排障**，保证系统在 Windows + GPU + 中文路径场景下稳定运行。

## 13. 已知局限与优化方向

1. **通用专区椭圆拉正未利用旋转角**：`warp_ellipse_to_circle` 直接用长短轴判断做水平/垂直拉伸，未先旋转对齐椭圆主轴，对旋转角度较大的椭圆拉正方向会有偏差，可作为优化点。

2. **矩形顶点排序为启发式**：接近 45° 旋转的矩形可能出现顶点错位，可改用主轴对齐的 `minAreaRect` 角点精确映射。

3. **知识库强绑定福州地域**：福州专区匹配库依赖人工维护，扩展新地区需补充对应单位名单。

4. **端到端指标未系统量化**：当前无统一的 benchmark 评估脚本，可补充精确率/召回率/字准确率对比实验。
